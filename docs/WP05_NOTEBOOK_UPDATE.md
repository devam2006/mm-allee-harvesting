## Live demos versus recorded benchmark

The two new demos use parameter learning rate 0.005, physics weight 0.5,
300 collocation points and up to 3000 L-BFGS iterations. Clean data use 500 Adam
steps and validation selection off; noisy data use up to 1200 Adam steps and
validation selection explicitly on, preserving Rohan's original default behavior.
Each fit has a 120-second CPU budget. The unchanged frozen 54-PINN/54-ODE benchmark
keeps its original shared settings and 10/18 clean PINN recovery count. These new
single-case illustrations are not a replacement or rerun of that benchmark.

The trajectory observer temporarily wraps only WP05's inverse-minimizer entry
point and restores it in `finally`; it does not replace SciPy's global function.
Native optimizer logging/cancellation errors propagate. The 3500-point curve
contains 500 actual Adam states and 3000 L-BFGS callback states, with no invented
final iteration; its last recorded values match the returned estimates.

New diagnostic prose distinguishes observed results from proposed explanations.
It avoids claims of exact parameter recovery, a convex ODE-fitting objective,
an exact L-BFGS inverse Hessian, analytical Jacobians not supplied by the code,
or guaranteed recovery from untested follow-up methods. Known exact N0,
extinction-padding and physics-supported held-out prediction remain explicit.
The precise structural ambiguity concerns all four unknown B parameters.
The method statements were checked against the implementation and official
[SciPy L-BFGS-B](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-lbfgsb.html)
and [least_squares](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)
documentation.

WP04 decisions (Prem, owner, 29 Oct 2026; PR reviewers to confirm): (1) the forward PINN engine uses **JAX** (CPU, float64) instead of PyTorch; this changes the declared PINN dependency in `pyproject.toml`, the CI `pinn` job and shared docs, and WP05 extends the JAX engine. (2) Network `(1,32,32,1)` tanh, hard initial condition `x_hat=x0+s*N(s)`, loss is the physics residual only, 100 uniform collocation points. (3) Optimiser: Adam for 1000 iterations (2/7 of 3500) then L-BFGS for 2500 iterations. (4) Forward runs use no solver labels; Model A trains only up to the reference extinction time. (5) Errors are reported in scientific notation, not percentages. (6) Fixed before the final sweep: the "inaccurate" label threshold (relative L2 > 5e-2), seeds 11/22/33, runtime cap 300 s per run, and parameter sets (a=0.2). (7) Scoring reference: DOP853, rtol 1e-12, atol 1e-14, generated in `experiments/wp04/run.py` because WP03's reference fixtures are not on main.

Activation and collocation decision (Prem, owner, 30 Oct 2026; reviewers to confirm): the final forward sweep uses **300 uniform collocation points, seeds 0/1/42 and the swish activation**, with the time input only scaled by the fixed constant T (no centring or nonlinear input map). Swish was selected from tanh / swish / sigmoid by a rule written before the run (most accurate runs out of 18 at relative L2 <= 5e-2; ties: smaller geometric-mean error): swish 17/18, tanh 11/18, sigmoid 10/18. The selection used the same seeds as the final sweep, so the reported accuracy is optimistic. This supersedes the earlier n=100 / tanh / seeds 11, 22, 33 sweep (12 of 18 accurate), which is kept as `artifacts/tables/wp04_forward_metrics_n100_tanh_seeds11-22-33.csv` with its manifest; the diagnostic experiment refers to that earlier design. Clustered early collocation (found in the diagnostic) was not adopted.

PR #6 review fixes and open integration decisions (Prem, 30 Oct 2026): the three code issues from the reviews are fixed in the WP04 branch: (1) a prediction with NaN/inf is invalid, never scored as accurate (error scores undefined, run label `invalid_prediction`, excluded from the activation-selection averages and counted as not accurate); (2) trained `harvest` is kept >= 0 and trained `a` in (0, 1) through both Adam and L-BFGS by an internal-value transform; (3) `load_checkpoint` returns the learned physical parameters, status and L-BFGS exit (it now returns a `ForwardResult`; the earlier `(params, config)` tuple is gone). Also adopted from the reviews: exact package versions are recorded (manifest and `*_requirements.txt`), PDF copies of figures for LaTeX, a near-zero error column, per-run `failed` handling and recording of the L-BFGS-B exit message. **Still to be settled with Rohan (WP05) in the separate integration branch:** which network/equation/optimiser utilities are shared and who maintains them, one agreed set of parameter transforms (the engine uses `harvest=raw**2`, `a=sigmoid(raw)`; the inverse trainer uses softplus/sigmoid with A in (0, K)), one status vocabulary (converged / validation stopped / budget exhausted / failed), and a forward-versus-inverse residual parity test. Raghav's review recommends keeping this JAX engine as the shared engine, because WP04 owns it, it is tested and CI is updated; the alternative of two engines under different module names would double what must be explained in the viva.
